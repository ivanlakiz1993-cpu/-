# Аудит производительности сайта

Дата: 25 октября 2026 года.

Проверены исходники главной, страницы испытаний, списка новостей, шаблона новости и двух юридических страниц; зависимости HTML/CSS/JS/JSON, размеры ресурсов, циклы анимаций и загрузчики. Поведение сайта не изменено. Это аудит исходников, а не измерение FPS, Lighthouse или сетевого трафика опубликованной версии. Проверка на реальных устройствах ещё нужна.

Размеры ниже — десятичные МБ исходных файлов, без HTTP-сжатия. Общий размер обследованных файлов вне скрытых каталогов — 144,88 МБ. Он включает исходники моделей и инструменты и не равен весу загрузки одной страницы.

## 1. Приоритетные изменения

### 1.1. Останавливать невидимую сцену испытаний

В `device-demo/app.js` в конце файла безусловно работает `renderer.setAnimationLoop`. Внутри каждого кадра пересчитываются 1000 дождевых частиц, обновляются GPU-буферы и рисуется сцена. Проверки видимости модели или нулевой прозрачности дождя здесь нет. На телефоне модель относится только к первой обложке, но этот цикл продолжает работать после её прокрутки.

Предложение: приостанавливать цикл вне видимой области и при скрытии документа; не пересчитывать дождь, когда он невидим; возобновлять по видимости, сбрасывая отсчёт времени. Учитывать `prefers-reduced-motion` для всей сцены. Состояние эффектов при возобновлении брать из актуального скролла. Это уменьшит расход процессора, GPU и батареи без удаления видимых эффектов.

### 1.2. Ограничить повторные обходы текста

В `site-text-reveal.js` MutationObserver наблюдает за всем `document.body`, включая дочерние узлы и текст. Любое подходящее изменение запускает `scan()`, который снова обходит все целевые тексты. `prepare()` клонирует элемент для сравнения текста ещё до проверки, что он уже подготовлен.

Счётчики в `testing-page.js` меняют `textContent` каждый кадр, даже если округлённая цифра осталась прежней. Их карточки исключены из анимации текста, но изменения всё равно запускают глобальный обход.

Предложение: игнорировать изменения в исключённых блоках до постановки `scan()` в очередь, проверять только изменившиеся текстовые блоки и записывать значение счётчика только при его фактическом изменении. Сохранить появление букв и поддержку динамического текста преимуществ и новостей.

### 1.3. Отложить загрузку и воспроизведение видео

`assets/project-cta-loop.mp4` — 14,34 МБ. В `index.html` оно подключено с `autoplay muted loop playsinline preload="metadata"`. Наличие autoplay означает, что metadata не является ограничением загрузки. В `script.js` есть обработчики готовности, но нет управления воспроизведением по видимости секции.

Предложение: подключать источник незадолго до появления секции, запускать видео при видимости и ставить на паузу при уходе. Оставлять имеющуюся заглушку до готовности видео. Затем отдельно сравнить варианты кодирования и разрешения; для совместимости сохранить MP4. Точный выигрыш после перекодирования пока не измерен.

### 1.4. Облегчить активную 3D-модель и карту инея

На странице испытаний `device-demo/app.js` сразу загружает:

| Ресурс | Размер |
|---|---:|
| `device-demo/device.glb` | 11,11 МБ |
| `device-demo/frost-height.png` | 4,74 МБ |
| `device-demo/brushed_normal.jpg` | 0,29 МБ |

Модель содержит 76 мешей, 77 примитивов и суммарно 287 112 записей вершин в атрибутах POSITION примитивов. Это характеристика файла, а не замер фактических draw calls. Дополнительно используются тени 2048×2048, до 2800 инстансов капель, 1100 кристаллов и 112 сосулек. DPR рендера ограничен значением 2, что всё ещё означает до четырёх пикселей рендера на один CSS-пиксель.

Предложение: сначала остановка невидимого рендера, затем измерение GPU-времени; после этого — профили качества по производительности, оптимизация геометрии/сжатие GLB и теней. Изменения геометрии должны сохранять имена и структуру, от которых зависят материалы и эффекты.

Отдельная возможность без изменения рисунка инея: `frost-height.png` — RGB PNG, 1254×1254, 8 бит на канал. Шейдер `frost-surface.js` использует только `.r`. Можно сохранить точные значения красного канала в одноканальном PNG. Это кандидат на уменьшение передачи файла без потери используемых шейдером данных; размер результата нужно измерить. Автоматически применять сжатие с потерями к normal/height-картам нельзя без сравнения результата.

## 2. Изображения, шрифты и новости

- Для основных фотографий нет набора размеров `srcset`/`sizes`. Телефон получает тот же файл, что широкий экран. Нужны варианты разрешения с корректным выбором по экрану и DPR.
- WebP уже используется, но вес остаётся большим: `news-forum.webp` — 1,02 МБ, `service-production.webp` — 1,01 МБ, вторая камера — 1,00 МБ, изображение сборки — 0,94 МБ. `news-forum.webp` даже больше исходного JPG: 1 015 448 против 888 226 байт. Расширение само по себе не гарантирует уменьшения веса.
- У основных картинок рабочих карточек уже есть `loading="lazy"`, а главная обложка правильно загружается сразу. При этом скрытые картинки переключаемых состояний имеют обычный `src`: lazy loading не гарантирует загрузку только активного состояния.
- `news-list.js` создаёт все карточки коллекции и задаёт `src` всем изображениям без lazy loading. При росте CMS нужны порционная выдача, lazy loading нижних карточек и миниатюры отдельно от фотографии статьи.
- В режиме локального JSON отдельная статья получает всю коллекцию через `listNews()`. Сейчас JSON маленький; для большой CMS лучше использовать уже предусмотренный запрос конкретной статьи.
- Главная использует CSS-фоны новостей, поэтому обычный атрибут lazy loading к ним неприменим. Можно подключать фон при приближении секции либо использовать изображение с сохранением внешнего вида.
- Активные шрифты: Yandex Sans TTF — 183,6 КБ и Bicubik OTF — 17,1 КБ. Возможны WOFF2 и подмножества с сохранением кириллицы, латиницы, цифр и нужной пунктуации. `font-display: swap` уже задан.

## 3. Кандидаты на исключение из публикации

Связи проверены консервативным статическим обходом строковых ссылок от шести публичных HTML-страниц через CSS, JS и JSON. Дополнительно проверены прямые упоминания отдельных старых файлов. Отсутствие в этом графе не доказывает ненужность для разработки, внешних ссылок или ручного просмотра.

| Группа | Размер | Что делать |
|---|---:|---|
| 36 оригиналов PNG/JPG, имеющих WebP-копии | 35,79 МБ | В текущем графе публичных страниц оригиналы не используются. Исключить из публикации, сохранив исходники отдельно |
| `assets/models/testing-equipment.glb` | 12,15 МБ | Старый экспорт; публичная страница использует `device-demo/device.glb` |

| `assets/helicopter.obj` | 8,36 МБ | Ссылок из проверенных текстовых файлов нет; текущий вертолёт строится в `helicopter-model.js` |
| `assets/fonts/inter-variable.ttf` | 0,88 МБ | Подключений не найдено |
| `device-demo/rain_drops_normal.png` | 2,34 МБ | Упоминается генератором загрузки; активная сцена эту текстуру не загружает |
| `testing-frost.js` | 10,2 КБ | Подключений не найдено |
| `testing-model.js` | 30,3 КБ | Подключён только в служебном `model-review.html` |
| `device-demo/vendor/RGBELoader.js` | небольшой | Не входит в граф публичных страниц; активная сцена создаёт отражения программно |

Первые четыре строки таблицы — суммарно 73,46 МБ без пересечения между этими группами. Это потенциальное сокращение состава публикации, не экономия загрузки посетителя: браузер уже не загружает эти файлы по найденным связям.

Также есть старые WebP-превью моделей и вариантов вертолёта, `model-before/after`, исходники `.blend`/`.blend1` и инструменты генерации. Лучше настроить отдельный состав файлов публикации. Исходники Blender и генераторы сохранять для дальнейшего редактирования. Удаление файлов из текущей версии само по себе не уменьшает прежнюю историю Git.

## 4. CSS, кеширование и совместимость

- `styles.css` — 51,24 КБ, `testing-page.css` — 53,04 КБ; в них много последовательных переопределений одних и тех же блоков и адаптивов. Очистка требует сравнения итоговых стилей на всех контрольных ширинах. Автоматическое удаление селекторов по одному снимку DOM может сломать раскрытый FAQ, меню, слайдеры и состояния анимации.
- Страницы новостей подключают `metrics-desktop.css`, хотя секции вертолёта в них нет. Общая таблица стилей тоже содержит много правил главной. Имеет смысл разделить общие стили и стили страниц, затем минифицировать публикуемые файлы.
- Одна и та же `styles.css` имеет разные query-версии на главной и внутренних страницах. Это разные URL для браузерного кеша. Нужна единая версия общего ресурса; изменённые файлы должны получать новый хеш/номер версии при публикации.
- Three.js загружается как локальный неминифицированный модуль размером 1,31 МБ. Сборка и минификация могут уменьшить передаваемый JS. Обновлять саму версию библиотеки ради этой задачи не требуется.
- У вертолёта чтение `gl.readPixels()` синхронное и считывает весь кадровый буфер при создании падающих символов. Это кандидат на кратковременную задержку при переходе. После профилирования можно читать уменьшенную сетку, соответствующую ASCII-ячейкам, сохранив расположение символов.
- На странице испытаний `WebGLRenderer` создаётся до `try/catch`. При недоступности WebGL полноценной обработанной заглушки здесь нет. Нужны обработка ошибки и восстановление после потери контекста. Сайт должен сохранять читаемый контент и при недоступной 3D-сцене.
- Новые CSS-возможности (`svh`, `cqw`, отдельные `translate`/`scale`, text-box) и GPU-фильтр теплового искажения нужно проверять на целевых браузерах. Нельзя обещать одинаковую работу на любых старых версиях; следует определить минимальные поддерживаемые версии и добавить необходимые fallback-правила.
- Переход между страницами намеренно ждёт завершения анимации покрытия: 560 мс плюс задержки плиток. Это часть воспринимаемой задержки перехода даже при быстрой сети. Менять её длительность стоит отдельно от технической оптимизации и с сохранением согласованного эффекта.
- HTTP-кеш, Brotli/gzip, сетевые размеры и поведение опубликованного хостинга в этом аудите не измерялись.

## 5. Рекомендуемый порядок работ и проверки

1. Остановка невидимой 3D-сцены и дождя, фильтрация MutationObserver, отложенное видео с паузой вне экрана.
2. Адаптивные изображения, точное сокращение каналов карты инея, WOFF2; оптимизация GLB после визуального сравнения.
3. Порционная загрузка новостей и картинок состояний карточек.
4. Состав публикации без архивных экспортов, оригиналов фото и служебных файлов; затем консолидация CSS и единые версии ресурсов.
5. Замеры до/после на одинаковой сети и устройствах: переданные байты, LCP/CLS, длинные задачи, время кадра, память и работа невидимых анимаций.

Для регрессии нужны обычный вход, обновление посередине страницы, прокрутка обратно, повторный проход, back/forward, изменение ориентации, возврат во вкладку, reduced motion и недоступный WebGL. Проверять Chrome/Edge/Firefox на компьютере, Safari на iPhone/iPad и Chrome/Samsung Internet на Android; отдельно слабый телефон. Эмуляция ширины экрана не заменяет проверку GPU и мобильного браузера.

Технические ориентиры: [MDN — отложенная загрузка](https://developer.mozilla.org/en-US/docs/Web/Performance/Guides/Lazy_loading), [MDN — рекомендации WebGL](https://developer.mozilla.org/en-US/docs/Web/API/WebGL_API/WebGL_best_practices).

## 6. Выполненные правки и ограничения

Внедрено 25 октября 2026 года:

- Рендерер испытаний работает только при видимой сцене и активной вкладке. Цикл приостанавливается при выходе сцены из области просмотра, скрытии вкладки и включённом `prefers-reduced-motion`; дождевые частицы не пересчитываются, когда дождь прозрачен. На уменьшенном движении сцена перерисовывается только по прокрутке/изменению размера.
- Ограничены DPR и размер карты теней для экранов до 1100 CSS-пикселей. Добавлен статичный кадр модели при недоступном WebGL и потере контекста; при восстановлении контекста снова включается сцена.
- Удалён глобальный наблюдатель изменений текста. Начальные тексты сканируются один раз, готовая разметка не клонируется без изменения текста, динамическая новость сканируется отдельно. Счётчик записывает значение только при изменении округлённого числа.
- Видео CTA получает источник за 240 пикселей до секции, воспроизводится только рядом с экраном и ставится на паузу при уходе. При `prefers-reduced-motion` и `Save-Data` источник не загружается; остаётся прежняя заглушка.
- Для 12 фотографий рабочих карточек и новостей добавлены размеры 640/1280/1920 и исходный размер. Их суммарный выбор 640w занимает 518 КБ вместо 7,12 МБ исходников (на 92,7% меньше для этого размера показа). Карточки главной загружают фон только перед появлением в области просмотра; у карточек услуг исходники не загружаются, пока соответствующее состояние не выбрано. Для фото новостей включены `srcset`, `sizes` и отложенная загрузка списка. Для фотографий камер также добавлены компактные размеры.
- Фото преимуществ загружается по мере приближения секции; следующие изображения загружаются по выбору карточки. Для них добавлены варианты разрешения.
- Карта высоты инея переведена из RGB в одноканальный PNG: красный канал всех 1 572 516 пикселей совпадает с исходником. Размер уменьшился с 4 741 635 до 1 343 724 байт (на 71,7%).
- Удалены неиспользуемые `testing-frost.js` и `assets/fonts/inter-variable.ttf` (вместе 886 797 байт). `device-demo/vendor/RGBELoader.js` оставлен: он не загружается страницами, но нужен `tools/check_device_export.py`. Для новостей удалено подключение домашней таблицы метрик. Общая версия `styles.css` синхронизирована на всех страницах, где она подключается.

Проверено после правок: синтаксис затронутых JS-файлов через Node.js 24, наличие всех локальных файлов из `srcset`/`data-srcset`, `git diff --check`, точное совпадение красного канала карты инея с версией из `HEAD`. Полного замера Lighthouse/FPS/сетевого трафика и проверки на физических телефонах здесь не было.

Пока не менялось:

- `device-demo/device.glb` и код вертолёта: доступных локальных glTF-компрессоров/профайлера нет, а изменение геометрии или `readPixels()` может повлиять на внешний вид и уже согласованную анимацию. Нужны сравнение рендеров и замер времени кадра до изменения.
- Шрифты WOFF2: локального конвертера нет. TTF/OTF оставлены без перекодирования.
- CSS не объединялся и не минифицировался: у проекта нет сборщика, а очистка каскада без визуального регрессионного просмотра может изменить состояния интерфейса.
- В списке новостей нет порционной загрузки: локальный JSON содержит 4 записи, а контракт CMS/API для пагинации не определён. Параметры запроса не выдумывались.
- Архивные модели, оригиналы фотографий, Blender-файлы и ресурсы генераторов сохранены как исходники. В репозитории нет конфигурации публикации с whitelist/исключениями; удаление источников ради размера текущего сайта повредило бы рабочие материалы и не гарантировало уменьшение скачивания браузером.
